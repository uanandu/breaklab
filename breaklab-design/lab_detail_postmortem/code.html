1 Executive Summary

Severity: P1 (Ingest Pipeline Stall)
Containerized batch ingest microservice worker-ingest-4 repeatedly crashed with exit code 137 (SIGKILL) under burst ingest loads. Root cause was an unconstrained JVM Ergonomics memory ceiling reading the 32GB host physical RAM instead of the 512MB container cgroup limit. The Linux kernel OOM killer abruptly aborted the Java process without application-level stack traces. Ingestion recovered with zero unrecoverable message loss via Kafka offset commits, though pipeline processing SLA degraded by 44 minutes.

2 Detection & Immediate Symptoms

MTTD: 3m 12s

Alert fired via Prometheus rule container_last_seen{container="worker-ingest-4"} == 0 during peak batch ingest. Automated restart loops triggered pagerduty escalation.

Host kernel dmesg ring buffer confirmed direct invocation of mem_cgroup_out_of_memory on PID 8192 with zero corresponding Java java.lang.OutOfMemoryError thrown in container logs, indicating a kernel-level cull before the runtime could trigger heap dumps.

3 Root Cause Analysis (RCA)

Cgroup CFS Subsystem Mismatch

The legacy base image openjdk:8u121-jre predates backported container awareness (introduced in OpenJDK 8u191+). By default, -XX:+UseContainerSupport was absent or inert.

// Memory Boundary Disconnect Topology
Host Physical Hardware Memory : 32.00 GB (32,768 MB)
Docker cgroup.max Memory Limit : 0.50 GB ( 512 MB)
JVM Ergonomics Default (-Xmx) : 8.00 GB ( 8,192 MB) <-- [1600% of cgroup]
Result: Once JVM Resident Set Size (RSS) crossed 512MB threshold, Linux OOM killer terminated the cgroup with SIGKILL (137).

4 Verified Resolution & Patch

Verified in Sandbox

Upgraded the runtime container to Temurin 17 LTS and configured container-aware heap sizing using percentage constraints rather than static host heuristics:

Dockerfile.production.patch unified diff 
@@ -1,7 +1,11 @@
- FROM openjdk:8u121-jre
+ FROM eclipse-temurin:17-jre-alpine
 
+ ENV JAVA_OPTS="-XX:+UseContainerSupport \
+                -XX:MaxRAMPercentage=75.0 \
+                -XX:+ExitOnOutOfMemoryError \
+                -XX:+HeapDumpOnOutOfMemoryError \
+                -XX:HeapDumpPath=/var/log/dumps"
 
 ENTRYPOINT ["sh", "-c", "exec java $JAVA_OPTS -jar /app/worker.jar"]
verified Validation: Sandbox sustained 1,200 msg/sec with RSS stabilized at 374MB under 512MB cap.
